# Native system share sheet contract

`openSystemShare({ title?: string; text?: string; url?: string }): Promise<void>` lets the MiniApp share text or a link through the existing system share utility (`share_plus`). It does not share files, open in-app forwarding, target a social app, or replace `openInviteDialog`. Calling it again while a sheet is open starts another share and does not reject.

The three fields are optional strings. The host trims them, treats blank `title` and `text` as absent, and requires non-empty `text` or a valid `url`. A supplied URL must be an absolute HTTP/HTTPS address with a host, even if text is also supplied. Null and other non-string values, an invalid URL, empty options, or a title alone reject with `INVALID_OPEN_SYSTEM_SHARE_OPTIONS`. Unknown fields are ignored. The SDK forwards the arguments and only applies `canIUse`; host support is checked before parsing options.

The host maps `title` to `ShareParams.title`, without using it as the email subject or adding it to the content. A URL without text maps to `ShareParams.uri`, allowing the system to fetch webpage metadata on iOS. Text without a URL maps to `ShareParams.text`. When both are present, their normalized values are joined with one added newline and passed as `ShareParams.text`, without setting `uri`: `share_plus` does not allow `text` and `uri` together. No link deduplication is performed. Titles and previews depend on the system and receiving app; their display is not guaranteed.

The promise resolves once the host has validated the options and triggered the sheet. Where the share utility already copies instead of presenting a sheet (non-Apple desktops and web), it copies the normalized text, URL, or combined content without the title. The promise resolves after that copy finishes, including when the copy fails and the host has shown its error toast. macOS still presents a sheet. The call does not wait for dismissal or return `ShareResult`. Existing native-failure copy handling and iPad/macOS safe anchors remain in place. A missing host callback rejects with `UNSUPPORTED_CAPABILITY` before the options are parsed. The method is not named `share` or `openShare`.

Existing URL-only calls remain valid, with URI sharing replacing the earlier plain-text mapping. Text and title support requires an updated host; `canIUse("openSystemShare")` does not detect support for individual fields. The host's two container entrypoints share the same parsing rules and typed callback. Other callers of the general share utility retain their existing behavior.
